[English](README.md) · [全部 Benchmark](../../README.zh.md)

**百万和千万事件的迁移、重算均完成；在每秒 50 条输入的测试负载下，没有丢弃消息。** 千万事件迁移约 60 分钟，250 万事件重算约 22 分钟。这是合成数据实测，不代表最低配置要求或最大接收能力。

## 测试条件

- Linux amd64，6 个逻辑 CPU，主机内存 9.49 GiB；单任务限制内存 7 GiB、swap 512 MiB，不限 CPU 配额。Go 1.26.2、go-sqlite3 v1.14.48、`sqlite_trace`，UTC。
- 120 天历史：热表 90 天、归档 30 天；500 个身份、50 个 Key、50 个模型、50 条规则，失败事件 1%。种子 `20260923`，时间锚点 `2026-09-23T00:00:00Z`。
- 独立生产者每 20ms 提供一条消息，测试缓冲容量 4,096，通过真实单 writer 写入 SQLite inbox；核对数量及消息哈希，随后实际处理为事件。不代表 CPA 网络端到端延迟。
- 产品基线 `4e41adc293f10469e4523a300432ace8b90dfc05`；历史升级通过场景额外包含两处 100 行回放批次调整，后提交于 `94eef02c`。[环境及二进制哈希](results/environment.json)标识实际测试对象。

## 历史升级与查询对比

独立的百万旧结构场景首次丢弃 2,620 条消息。将旧五维和 Latency 回放批次从 1,000 缩至 100 行后，同一数据集及输入速率下丢弃为零。迁移总时长从 547.992 增至 772.901 秒；提供至落盘的最长延迟从 134.339 降至 **26.001 秒**，仍存在临时积压。通过场景核验全部 48,064 条接收消息，333,333 条事件重算耗时 188.363 秒。失败场未执行重算和追赶，对应零值表示未测量。

另用旧版 `54a43cb3` 与新版 `4e41adc2` 顺序启动真实 HTTP 服务，每个接口预热一次、采样五次。同一 119 天范围，两版均返回 991,361 次请求、2,672,835,362 Token：

| 接口 | 旧版中位数 | 新版中位数 |
| --- | ---: | ---: |
| Overview | 1,301.07 ms | 71.02 ms |
| Analysis | 1,706.19 ms | 1,757.33 ms |

五次样本不足以证明 Analysis 稳定退化。对照使用返回 404 的本地模拟 CPA，排除了注入消息所在日期；不是千万查询对照或并发用户测试。
